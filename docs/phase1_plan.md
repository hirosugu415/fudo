# フェーズ1（土台）実装計画

この文書は、フェーズ1を実装する担当者（Claude）向けの計画書である。仕様の正本は `SPEC.md`。この文書は SPEC.md を前提に、ユーザーと合意済みの判断と実装方針をまとめたもの。

## 0. 実装前に必ず守ること

- **SPEC.md を最初から最後まで読むこと。** 特に第1章「絶対に守る設計原則」は、実装のすべての場面で守る。迷ったら次の2点を自問する。
  - これは神の手になっていないか
  - 都市全体の目標を持たせていないか
- **最優先は内部の数値モデル。** 見た目は最小限でよい。
- **係数はすべて設定ファイル（YAML）に置き、単位と根拠をコメントで書く。**
  - 根拠は出典か理由。推定値なら「推定」と明記する。
  - コード側には既定値やフォールバック値を一切書かない。設定キーが欠けていたら起動時にエラーにする。
  - 物理定数のように変わらない値（1日の秒数など）は例外。
- **仕様書にもこの計画書にも書かれていない判断が必要になったら、勝手に決めずにユーザーに質問する。**
- 作業の順番：
  1. 実装する
  2. 第14章のうち再現性のテストを通す
  3. 最後に、ビューアの起動方法（地形と川が表示されるもの）をユーザーに伝える

## 1. ユーザーと合意済みの判断

| 項目 | 決定 |
|---|---|
| Python | 3.13（PCに入っているもの）で `.venv` を作る。SPEC の推奨は 3.12 だが、Numba 0.61 以降が 3.13 に対応しているため、この選択で合意済み |
| 再現性の範囲 | 同じPC・同じライブラリのバージョンでビット単位まで一致させる。OSをまたぐ一致（数学ライブラリの実装差）は保証しない。使ったバージョンをマニフェストに記録する |
| ユーザーの操作 | 「マップを生成」と「シミュレート開始」の2つだけ。自然はすべて世界シードから生成する（SPEC 原則4・第4章は書き換え済み） |
| 生成する世界の範囲 | 温帯の日本的な範囲（緯度およそ25〜45度）。海に面するか内陸の盆地かもシードで決まる。範囲は生成器の設定ファイルに置く |
| 地形 | ノイズで隆起量を決め、浸食・堆積シミュレーションで地形を作る。川と谷が物理的に整合すること。堆積で沖積平野・扇状地ができ、沖積層はその結果から決める |
| 蒸発散 | 気温と日の長さから計算する（Hamon法）。係数は設定ファイルに置き、水量保存のテストにも含める |
| マップ外からの川 | 生成する。外側の集水面積も生成し、浸食にも反映する |
| 気温 | 緯度から計算し、標高と海からの距離で補正する |
| 降水 | 緯度・海からの距離・山の風上と風下から計算し、地形と整合させる |
| 年ごとのゆらぎ | 気温と降水に入れる。シードから決定的に生成する。固定の起点の年（1700年）から生成するので、ウォームアップ期間を足しても1870年以降の気候は変わらない |
| 終了年 | 既定は 2150-12 |
| 実行シード | エージェント用の乱数は、世界シードとは別の実行シードから作る。指定がなければ世界シードから決定的に作る。run_id に含める。フェーズ1では仕組みだけ |
| マップ端から入る空気の湿り気 | 端ごとの外側の地形（海・平地・山地）と外側の海までの距離から決める。外部世界の地形構成と矛盾しないようにシードから生成する |
| 地下水 | 線形貯留モデルで入れる（基底流量） |
| フェーズ1で生成する資源 | 地質＋鉱物＋森林＋漁場 |
| 後のフェーズに回すもの | 土壌の肥沃度・水はけ（フェーズ2で農業と一緒に）、景観価値、災害の性質（フェーズ7）。どれも名前付き乱数ストリームで後から追加し、既存の世界は変えない |
| 外部世界 | 性質（大都市の接続点と規模、地形構成、人口成長の傾向、景気変動の大きさ）をシードから生成する。外部世界の**動き**（第8章）はフェーズ3 |
| 物理法則 | 画面に出さない。設定ファイルの既定値で固定し、世界シードとは別に管理する。同じ世界のまま物理法則だけを変えて比較できるようにする |
| Three.js | CDNは使わない。プロジェクト内に同梱し、ネット接続なしでビューアが動くようにする |

## 2. フェーズ1の範囲

1. 設定ファイルの読み込みと検証。生成器の設定、物理法則の設定、シミュレーションの設定を分けて扱う
2. 乱数シードの管理（名前付きの独立したストリーム）
3. 世界の生成。次の順に、物理的に整合するよう計算する

   3. 隆起と浸食による地形（気候と交互に計算）

   5. 気候の平年値
   6. 水系
   7. 鉱物、森林、漁場

4. 「今回の世界」の説明を生成する
5. 月次の自然シミュレーション：年ごとの気候のゆらぎ、積雪と融雪、地下水、流量
6. スナップショットの保存
7. 最小ビューア：「マップを生成」「シミュレート開始」、世界の説明、地形の高さ、川の線、月のスライダー

**フェーズ1にはエージェントがいない。** それでも、神の手が後から入り込まない構造にしておく。
- `world/` と `nature/` は自然だけを扱う。人間側の概念（町・道・用途など）を import しない。テストで機械的に確認する。
- 月次ループには「自然の更新 → （将来）エージェントの判断 → 市場」という差し込み口だけを用意する。上から何かを配置する API は作らない。

## 4. 主要な設計

### 4.1 識別子とシードの分離
- **world_id**：`hash(世界シード, 生成器の設定のハッシュ, 生成器のバージョン)`
  - 物理法則とシミュレーションの設定は含めない。物理法則を変えても世界は同じ、ということをこれで保証する。
- **run_id**：`hash(world_id, 実行シード, 物理法則の設定のハッシュ, シミュレーションの設定のハッシュ)`
- **実行シード**：エージェントの確率的な選択に使う（フェーズ2以降）。指定がなければ、世界シードから名前付きストリーム `"run_seed"` で決定的に作る。`fudo run --run-seed N` で指定できる
- 設定のハッシュは、YAMLを読み込んで正規化（キーを並べ替えたJSONなど）してから SHA-256 を取る。コメントの変更はハッシュに影響させない。
- 世界シードは 63 ビットの整数。
  - 「マップを生成」でシードが空欄のときは、サーバーが OS の乱数（`secrets`）から作る。作ったシードは必ず表示して記録する。
  - ユーザーがシードを入力すれば、同じ世界を再現できる。

### 4.2 乱数（原則5）
- 名前付きストリーム：`Generator(PCG64(SeedSequence(world_seed, spawn_key=(crc32(名前),))))`
  - 名前の例：`"geology"`, `"uplift"`, `"climate_anomaly"`, `"minerals.coal"` など
- ストリームを追加しても、既存のストリームの乱数列は変わらない。
- 1つのストリームの中で、乱数を引く順序は固定する（辞書の反復順に依存しないよう、名前で並べてから回す）。
- 年ごとの気候のゆらぎは `climate_anomaly` ストリームから、**1700年を起点に**年の順に引く。シミュレーションの開始年がいつでも、ある年のゆらぎは同じになる。
- エージェント用の乱数は、実行シードから作る名前付きストリームで取る（`rng.run_stream(run_seed, 名前)`）。

### 4.3 決定性
- Numba は `parallel=False`、`fastmath=False` にする。`cache=True` は使ってよい。
- 集計の順序は配列の順序で固定する。
- float の書き出しは `float32` か `float64` に明示して統一する。
- 優先度付きキューで値が同じ要素の順序は、セル番号で決まるようにする（Priority-Flood で特に注意）。

### 4.4 世界の生成アルゴリズム

いずれも係数は設定ファイルに置く。かっこ内は根拠の候補で、設定ファイルのコメントに採用した出典を書く。

1. **枠組み**
   - 緯度：設定した範囲から一様に選ぶ。
   - 海の配置：海に面するマップ端（0〜2辺）を確率で選ぶ。0辺なら内陸の盆地になる。
   - 風：卓越風の向き（緯度帯から決める）と、季節風の向きと強さ（冬は大陸側から、夏は海側から）をシードで決める。
2. **地質**
   - 岩石の種類（例：花崗岩、堆積岩、石灰岩、火山岩など。種類は設定で追加できる）の分布を、ドメインワープしたノイズで作った領域として生成する。
   - 岩石ごとに次を持たせる。
     - 浸食されやすさ（流水による下刻の係数 K への倍率）
     - 岩盤の硬さ
     - 地盤の軟弱さ
     - 鉱床のできやすさ
   - 沖積層（川が運んだ土砂が積もった層）は浸食の結果として後から決める。
3. **隆起と浸食**
   - 隆起量 U：fBm ノイズで作り、海の辺に向かって低くなる傾きを加える。
   - 浸食と堆積：Yuan et al. (2019) の式 `dz/dt = U − K·Q^m·S + (G/Q)·Qs + D·∇²z` を、Braun & Willett (2013) の陰解法（n=1）を堆積付きに拡張した方法で解く。
     - Qs：上流で正味に削られた土砂の量（m³/年）。勾配が緩いところで (G/Q)·Qs の分だけ積もる
     - Qs は上流側の新しい標高に依存するので、各時間刻みの中で反復計算する（Gauss-Seidel 型。収束の判定と最大回数は設定で決める）
     - 窪地（湖）は土砂の受け皿とする。下刻はせず、流れ込んだ土砂が積もる。湖の水面の高さまでで止める
     - 浸食の前後の差から沖積層の厚さを追跡する。厚さがしきい値を超えたマスを沖積層とする
     - G：堆積の係数（無次元）
     - Q：降水量（蒸発散を引いた流出量）で重みを付けた集水量
     - K：岩石と気候によって変わる
     - D：斜面の拡散係数（Fernandes & Dietrich など）
     - m/n：およそ 0.5（Whipple & Tucker 1999 など）
   - 境界条件
     - 海の辺は基準面（標高を固定）にする。
     - 陸の辺は、生成した「外側の地形」の標高で固定する。
     - マップ外から流れ込む川：陸の辺の流入点に外側の集水面積 `A_ext` を加える。流入点の数・位置・`A_ext` はシードで決める。
   - 一定回数ごとに気候の平年値（後述の5）を計算し直し、Q と K に反映する。地形と気候を交互に計算して整合させるため。
   - 256×256 で1分以内を目安にする（SPEC にない目安。大きく超えるならユーザーに相談する）。
4. **海岸線と海底**
   - 海面（標高0）以下で、海の辺につながる部分を海とする。
   - 海底の水深は、海岸からの距離とノイズで生成する。漁場の判定に使う。
5. **マップ端から入る空気の湿り気**
   - 陸の端ごとに、外側の地形を「平地」か「山地」に決める。確率は外部世界の地形構成（山・平地の割合）に従う。海の端は「海」とする。
   - 端ごとに、外側の海までの距離を生成する。島の割合が大きい外部世界ほど短くする。
   - 入ってくる空気の水蒸気量 ＝ 気温（海の端なら海面水温）から決まる飽和水蒸気量 × 外側の海までの距離による減衰 × （山地なら）山を越えて乾く分の倍率。
   - 外側の地形は、浸食の境界条件（陸の端の固定標高）にも使う。
6. **気候の平年値**（12か月分）
   - 気温：緯度から海面での年平均気温と年較差を出す。係数は気象庁の平年値（1991〜2020年）を緯度で回帰したものなど、出典を明記する。
     - 大陸度：海からの距離で年較差を大きくする。
     - 気温減率：6.5 K/km（国際標準大気）。
   - 降水：月ごとの風向に沿って、上流から下流へ順に水蒸気量を計算していく（移流）。
     - 海の上で水蒸気が補給される。
     - 基本の降水と地形性降雨（風が斜面を上る成分 `風速·∇z` に比例）で水蒸気が減る。
     - その結果、風上の斜面で多く、風下で少なくなる（雨陰）。
     - 基本の水蒸気の量は緯度と月から決める。
   - 月の降水を気温で雨と雪に分ける。
   - 蒸発散：Hamon 法（気温による飽和水蒸気密度 × 日の長さ）で可能蒸発散量を出す。実際の蒸発散は土壌の水分で上限をかける。浸食の重みには、平年値の流出量（降水 − 蒸発散）を使う。
   - 気候区分：月平均気温と月降水量からケッペンの気候区分を判定し、説明文に使う。
7. **水系（変化しない部分）**
   - Priority-Flood（Barnes et al. 2014）で窪地を埋める。埋まった深さが設定値を超えたマスは湖とする。
   - D8 で流向を決め、集水面積を累積する。
   - 外から流れ込む川について、外側の集水域の平均標高と気候も生成して保存する。月ごとの流入量の計算に使う。
8. **鉱物**
   - 鉱物の種類ごとに、できやすい岩石の上に鉱床の中心を確率で置く。強度はポアソン過程で、設定ファイルに置く。
   - 鉱床ごとに次を持たせる。
     - 範囲（マスの集合）
     - 埋蔵量（対数正規分布）
     - 品位
     - 深さ
   - 例：石炭は堆積岩、石灰岩は石灰岩、銅・鉄は火山岩や貫入岩との境界。対応関係は設定で決める。
9. **森林**
   - 気候から森林の型を決める。例：吉良（1945）の暖かさの指数・寒さの指数で、常緑広葉樹・落葉広葉樹・針葉樹・亜高山帯などに分ける。
   - 型ごとに成長速度と最大蓄積量を持たせる。
   - 初期の蓄積量は自然の上限とする。人間による利用はフェーズ2のウォームアップ期間で起きる。
10. **漁場**
   - 設定した水深より浅い海と、一定以上の流量がある川を漁場とする。
   - 資源量の上限と回復速度（ロジスティック成長、Schaefer モデル）を持たせる。
11. **外部世界の性質**
    - 接続点の候補：外から流れ込む川の上流側の端、海の辺、陸の辺で標高が低くなっている鞍部（峠）。
    - 候補から1〜数か所を選び、大都市の初期規模（対数正規分布）を付ける。
    - 外部世界の地形構成（山・平地・島の割合）、人口成長の傾向、景気変動の大きさを、設定した範囲から生成する。
    - フェーズ1では値を保存するだけで、動きは計算しない。

### 4.5 「今回の世界」の説明（`describe.py`）
- 構造化データ（JSON）と、そこから組み立てる日本語の文章の2つを出力する。
- 載せる内容：
  - 緯度
  - 気候区分
  - 年平均気温
  - 年降水量と月ごとの分布
  - 積雪の多い月
  - 主な山（設定した半径の中で最も高い山頂を、標高の高い順に上位N）
  - 主な川（年平均流量が大きい順に上位N。外から流れ込む川かどうかも示す）
  - 湖
  - 海の向き
  - 鉱物（種類・場所・埋蔵量・品位・深さ）
  - 森林の型の分布
  - 漁場
  - 外部の大都市（どの端に、何を経由してつながっているか、規模）
  - 外部世界の性質
- 場所は「北西部」「中央やや東」のように方角で表す（区分は設定で決める）。
- 固有名詞は作らない。

### 4.6 月次の自然シミュレーション
各月に次を順に計算する。
1. **年ごとのゆらぎ**：1700年から設定した終了年までの、毎年の気温の偏差（AR(1)過程）と降水量の倍率（対数正規分布、AR(1)過程）を、生成時に1本の系列として作っておく。月次の計算では、その年の値を引くだけにする。大きさと持続性は設定で決める。
2. **その月の気温と降水**：平年値にゆらぎを加える。
3. **積雪と融雪**：度日法で計算する。
4. **蒸発散と土壌の水分**：雨と融雪が土壌に入り、蒸発散（Hamon法、土壌の水分が上限）で減る。容量を超えた分があふれる。
5. **地下水**：あふれた水の一部が浸透し、線形貯留モデルで基底流量として出ていく。残りは表面を流れる。
6. **流量**：表面の流出と基底流量を D8 に沿って下流へ累積し、外から流れ込む川の流入量を加える（m³/s）。
   - マップは25km四方で、川が流れ切るのに1日もかからない。そのため、月の中での流下の時間は無視する。
7. **スナップショットを書く**
   - 森林と漁場はフェーズ1では変化しない（利用する主体がいないため）。

性能の目標：1か月あたり0.1秒未満（SPEC 第2章）。

### 4.7 保存
- `worlds/<world_id>/`
  - `manifest.json`：シード、設定のハッシュ、ライブラリのバージョン
  - `world.json`：説明文
  - `static.npz`：標高、地質、海と湖、流向、集水面積、気候の平年値、鉱床、森林、漁場、川の線（ポリライン）
- `runs/<run_id>/`
  - `manifest.json`：world_id、物理法則のハッシュ、書き出し済みの最終月
  - `months/NNNNN.npz`：その月の積雪・流量・地下水・気温・降水（float32、圧縮）
- 書き込みは一時ファイル → リネームの順にする（原子的な書き込み）。マニフェストの「書き出し済みの最終月」を更新するのは、その月のファイルが揃ってから。
- 計算は別プロセスで進む。ビューアは書き出し済みの月までしか進めない（SPEC 第2章の実行モデル）。

## 5. テスト

- `test_reproducibility.py`（**第14章の再現性。必ず通す**）
  - 同じシードで、別プロセスで2回世界を生成する。`static.npz` の全配列のバイト列と `world.json` が一致すること。

- `test_hydrology.py`

## 8. 実装で決めた細部（フェーズ1の実装時に追記）

仕様と計画の範囲内で、数値計算上の都合から決めたこと。後のフェーズで見直す場合はここを参照する。

- **マップ端の境界条件**
  - 海の端と平地の端は、標高を固定した「水の出口」にする。
  - 山地の端は、標高を固定した「壁」にする（水は出ていかない）。
  - どの端も開いていない（全部山地で海もない）世界では、山地の端の1か所に峡谷の出口を作る。
- **外から流れ込む川**：山地の端にだけ置く。平地の端は境界が開いているので、入ってきた川がすぐ出てしまうため。
- **地形の生成の段階**（平野が少ないという指摘を受けて追加。ユーザー合意）
  1. 300万年の浸食・堆積（海面0）。
  2. 最終氷期の低海面期（海面 −120 m、3万年）。
  3. 完新世（海面0、7000年）。
- **海に入った土砂**
  - 外洋に面した帯（海の端から 3 km）に届いた土砂は、沖へ運ばれる。
  - 沈む場所（沈降盆地・海岸の沈降域）が海に沈んだ部分（湾）に入った土砂は、湾を埋める（割合は `basin_trap_fraction`）。
  - 完新世には、河口に届いた土砂の一部（`marine_trap_fraction`）で、河口から近い順に海を海面の高さまで埋める。
  - 全期間で海に土砂を積もらせる方式も試したが、海がほぼ埋まるため採らなかった。
- **沈降盆地**
  - 隆起のノイズが低い場所を沈ませる。
  - 速さの上限は「隆起する山地から出る土砂の体積 × `basin_fill_ratio`」。
  - 山地の端の隆起の上乗せは、隆起している場所だけを強める（低地は持ち上げない）。
- **窪地（湖）**
  - 土砂の受け皿とする（下刻しない）。
  - 流れ込んだ土砂は、入口から近い順に湖の中へ横に広げて、水面の高さまで積もらせる。
  - 満杯になってあふれた分は、同じ時間刻みのうちに下流の湖・海・マップの外へ運ぶ。
  - 以前は流向に沿った1本の筋にしか積もらず湖が埋まらないバグがあったので、直した。
- **流向**
  - 浸食の計算中は、下り方向の近傍から勾配に応じて確率的に選ぶ（Freeman 1991 の多方向流の時間平均）。
  - 地形ができた後の水系は最急降下の D8 とする。ただし、平らな面の数値上の傾きはマスごとにばらつかせ、平野の流路が直線にならないようにする。
- **平野の微起伏**：沖積層の上にだけ、振幅 0.6 m の微起伏（自然堤防・後背湿地）を加える。
- **斜面の拡散**：陰解法（行・列方向の後退オイラー）で解く。
- **臨界勾配**：35° を超える斜面は、超えた分を低い側へ崩す（質量保存）。浸食の各ステップの最後に行う。
- **山地の端**：標高を固定しない（以前は固定した壁で、端に段差ができた）。水が外へ出ないだけの境界。
- **気候**：夏の季節風は南東〜南南西から吹く（ユーザー合意）。季節風の向きによらない雨（梅雨・台風・夕立）を月降水量に加える（`climate.yaml` の `rain_systems`）。
- **保存**：Windows で読み手がいると置き換えに失敗するので、再試行する（`storage.yaml` の `replace_retry`）。ビューアから起動した実行の出力は `runs/<run_id>.log` に残す。
- **沖積層の厚さ**
  - 川による下刻・堆積の増減で追跡する。
  - 斜面の拡散でずり落ちた土砂（崖錐）は数えない。拡散で削られた分は差し引く。
- **堆積面が平らかどうかの判定（テスト）**：流れの方向に沿った勾配で測る。中心差分では、細い谷を埋めた堆積面でも谷壁の勾配を拾ってしまうため。
- **地形性降雨**：降水効率に上限（`orographic_max_factor`）を設ける。勾配の大きい斜面で降水が発散するのを防ぐため。
- **大陸度**：年較差を大きくするだけでなく、年平均気温も下げる（`mean_shift_c`）。
- **外側の集水域の気候**：気温はその端の外側の海までの距離と平均標高から計算する。降水はマップ内の陸の平均と同じとみなす。
- **主な山**：設定した半径の中で最も高い山頂を選ぶ。地形的プロミネンスは使わない。
- **ケッペンの気候区分**：しきい値（Kottek et al. 2006）も `description.yaml` に置く。
- **月の気温・降水の保存**：格子の値は保存しない。「平年値（static.npz）＋その年のずれ（スカラー）」として保存し、そこから再現できるようにする。

## 1. このプロジェクト

- **何をつくっているか**：都市創発シミュレーター。地形・資源・物理法則だけを与え、人間や企業が自分の利益で行動した結果として、都市が生まれ・育ち・衰える様子を観察する。1ステップ = 1か月、明治初期（1870年）から近未来まで。
- **仕様の正本**：[SPEC.md](../SPEC.md)。特に第1章「絶対に守る設計原則」を、実装のすべての場面で守る。
  - 神の手の禁止。建物・道・人口は、エージェントの判断の結果としてだけ生まれる。
  - 都市全体の目標を持たない。
  - 技術は名前ではなく効果（コストの数値）で表す。
  - 完全な再現性。
  - マジックナンバー禁止。係数はすべて設定ファイルに置き、単位と根拠を書く。
  - 強化学習やキャリブレーションは使わない（ロジット）。
- **迷ったら自問すること**：「これは神の手になっていないか」「都市全体の目標を持たせていないか」。
- **場所**：`C:\Users\kurow\Desktop\playgrounds\fudo`（Windows 11、Python 3.13、`.venv`）。

### 5.2 ID と再現性

- `world_id` = hash(世界シード, 生成器の設定, 生成器のバージョン)
- `run_id` = hash(world_id, 実行シード, 物理法則, シミュレーションの設定, 行動の設定)
- 実行シードを指定しなければ、世界シードから決定的に作る。
- 乱数は名前付きストリーム（`rng.stream(world_seed, 名前)`、`rng.run_stream(run_seed, 名前)`）。ストリームを追加しても既存の乱数列は変わらない。
- 年ごとの気候のゆらぎは、1700年を起点に生成する。開始年やウォームアップの長さを変えても、同じ年の値は同じ。
- 再現性は、配列の内容のハッシュで確かめる（npz の zip には時刻が入るので、ファイルのバイト列では比べない）。

### 5.4 シミュレーション

- **ウォームアップ**（既定100年、1年ごと）：何もない土地に、外部の大都市の接続点から入植者が来る（来るかどうかは外の効用と比べて本人が決める）。
- **本番**（1870年1月から毎月）：水収支 → 社会。

## 7. よく使う手順とつまずきやすい点（Windows）

- **文字コード**：コマンドの前に `export PYTHONUTF8=1`（Bash）を付ける。CLI は自分で UTF-8 に切り替える。
- **よく使うコマンド**
  - 世界の生成：`.venv/Scripts/fudo generate --seed 2`
  - ビューア：`.venv/Scripts/fudo view` → http://127.0.0.1:8765/
- **ビューアから起動した実行のログ**：`runs/<run_id>.log`
- **長い処理**（ウォームアップ100年 ≒ 4分、test_society ≒ 7分、全テスト ≒ 17分）：Bash の `run_in_background` で実行し、通知を待つ（10分の制限がある）。
- **パッチの当て方**：Bash のヒアドキュメントの中に日本語や引用符の多い Python を書くと、壊れることがある。パッチのスクリプトはファイルに書いてから実行する（`rep(path, old, new)` で、置き換え対象が1つだけあることを確かめる方式が安全）。
- **grep**：同梱の `three.module.min.js`（1行が巨大）に当たると出力が溢れる。`--include=*.py` で絞る。
- **確認用の作業ファイル**：スクラッチパッド（セッションごとに変わる）に置く。地図の PNG は、matplotlib がなくても NumPy と zlib（PNG のチャンクを自分で組み立てる）で書ける（`lessons_learned.md` 第2章の3）。数値の一覧だけでは見落とすことが多いので、地形や町を変えたら地図にして見る。
- **プロファイル**：重いときは `cProfile` で `cumulative` 順に見る（フェーズ2の高速化はこの手順で行った）。
- **世界を作り直す必要**：生成器の設定を変えたら world_id が変わり、前の世界の実行はできない（エンジンが止める）。
